Vamos a trabajar juntos en este proyecto como parte de un curso de IA Generativa usando Claude.

Quiero que, antes de realizar cualquier cambio en el código, hagas un análisis completo del proyecto siguiendo exactamente este orden:

### 1. Analizar el README.md

Primero, localiza y lee completamente el archivo `README.md`.

Identifica y explica:

- El objetivo general del proyecto.
- El problema que se pretende resolver.
- Las funcionalidades requeridas.
- Los requisitos técnicos.
- Las restricciones o condiciones que se indiquen.
- Los criterios de aceptación, si existen.
- Cualquier entregable esperado.
- Cualquier detalle que pueda afectar la implementación.

No asumas requisitos que no estén indicados en el README. Si encuentras ambigüedades, inconsistencias o información que falte, señálalas claramente.

### 2. Analizar el proyecto completo

Después de entender el README, analiza la estructura completa del proyecto.

Revisa, según sea necesario:

- Estructura de directorios.
- Archivos de configuración.
- Código fuente.
- Dependencias.
- Tests existentes.
- Scripts.
- Documentación adicional.
- Configuración de build o ejecución.
- Docker/Docker Compose, si existen.
- Archivos relacionados con IA, APIs, bases de datos u otros servicios, si existen.

Quiero que determines qué partes del proyecto ya están implementadas, cuáles están parcialmente implementadas y cuáles faltan.

También identifica:

- Problemas o inconsistencias existentes.
- Código que podría reutilizarse.
- Componentes que sería necesario modificar.
- Componentes que sería necesario crear.
- Dependencias o tareas que tengan relación entre sí.
- Riesgos técnicos que debamos considerar.

No realices cambios en ningún archivo durante este análisis.

### 3. Crear un plan de actividades

Una vez terminado el análisis, crea un plan de trabajo para cumplir las especificaciones del `README.md`.

Organiza el plan en fases o etapas y, para cada actividad, indica:

1. **Actividad**
2. **Objetivo**
3. **Archivos/componentes involucrados**
4. **Qué habría que implementar o modificar**
5. **Dependencias con otras actividades**
6. **Resultado esperado**

Ordena las actividades de acuerdo con sus dependencias y prioridad, de manera que podamos ejecutarlas posteriormente paso a paso.

Si consideras que alguna decisión técnica requiere que yo elija entre varias alternativas, presenta las opciones y explica brevemente las ventajas y desventajas de cada una. No tomes decisiones importantes por tu cuenta. También indica si es necesario utilizar diferentes modelos para ciertas tareas.

### 4. Revisión antes de implementar

Al final, incluye una sección llamada **"Preguntas y decisiones pendientes"** donde indiques cualquier punto que necesitemos aclarar antes de comenzar a modificar el proyecto.

También incluye una sección **"Resumen del plan"** con una lista ordenada de las principales etapas que propones.

### Restricciones importantes

- **NO modifiques ningún archivo.**
- **NO escribas código nuevo en el proyecto.**
- **NO ejecutes cambios que alteren el estado del proyecto.**
- No instales dependencias.
- No elimines ni renombres archivos.
- No hagas commits.
- No intentes implementar todavía ninguna de las funcionalidades.

En esta primera etapa quiero únicamente **entender el proyecto y definir el plan de trabajo**.

Cuando termines, presenta tu análisis y el plan para que podamos revisarlo juntos. Después de revisar el plan, te indicaré qué ajustes hacer y, únicamente cuando yo lo autorice explícitamente, comenzaremos con la implementación.
